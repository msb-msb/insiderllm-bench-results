# ESP32-S3 N16R8, esp32-ai TinyStories stop at end-of-story (STOP_AT_EOT), 2026-10-11: P1, P2 held

Results record for `~/Desktop/esp32-llm/evals/eot-flag-01/PREREG.md`. The firmware never stopped on `<|endoftext|>`
(id 0): it decodes to zero bytes, so a greedy run crosses the story boundary and starts a new story
(`../tamanna-decode-01-2026-10-10/`). This adds an opt-in stop, applying audit-01 §4.3's patch. It is stacked on the
simd-core build. No timing sweep: one run per setting.

  from the deploy.sh header is `#define VOCAB_EOT_ID 0`.
- **Defines:** `-DLOGIT_CHECKSUM=1 -DSTOP_AT_EOT=0` and `-DLOGIT_CHECKSUM=1 -DSTOP_AT_EOT=1`.

## Result (240 MHz, one run each)

| setting | tokens | text bytes | text sha256 | first id 0 | throughput line |
|---|---:|---:|---|---|---|
| STOP_AT_EOT=0 | 200 | 763 | `b9abf55b…c467` | step 132, after 479 generated bytes | 18.87 tok/s (50.4 ms/token) |
| STOP_AT_EOT=1 | 132 | 499 | `30b10658…4d8c` | step 132 (stopped) | 20.65 tok/s (45.6 ms/token) |

- **The cut point.** 499 = 4 (`>>> `) + 16 (prompt) + 479. At that offset the STOP_AT_EOT=0 text continues
  `\nOnce upon a time, there was a little gi…`: the restart into a new story.
- **Not a speedup.** The STOP_AT_EOT=1 ms/token is not comparable: a 132-token run averages attention over a shorter
  KV cache (attn 13.0 against 17.9 ms).
- **Benchmark builds** keep STOP_AT_EOT=0.
